# AgentOrchestra: Orchestrating Multi-Agent Intelligence with the Tool-Environment-Agent (TEA) Protocol

**Authors:** Wentao Zhang, Liang Zeng, Yuzhen Xiao, Yongcong Li, Ce Cui, Yilei Zhao, Rui Hu, Yang Liu, Yahui Zhou, Bo An  
**Affiliations:** Skywork AI, Nanyang Technological University  

## Abstract
Recent advances in LLM-based agent systems have shown promise on complex, long-horizon tasks, but existing agent protocols (e.g., A2A and MCP) do not adequately support lifecycle-aware coordination across agents, tools, and environments. To address this limitation, we introduce the **Tool–Environment–Agent (TEA) protocol**, a unified abstraction that models these components as first-class, versioned resources with explicit lifecycles. TEA supports end-to-end context and version management, improving traceability and reproducibility, while also enabling continual self-evolution of agent-associated components. Building on TEA, we present **AGENTORCHESTRA**, a hierarchical multi-agent framework in which a central planner coordinates specialized sub-agents and dynamically extends capabilities during execution. Experiments on four challenging benchmarks show that AGENTORCHESTRA consistently outperforms strong baselines; in particular, it achieves **89.04% on the GAIA Test set**, placing it among the leading methods.

---

## 1. Introduction
Current agent protocols (like Google's A2A and Anthropic's MCP) fall short as a general substrate for scalable agents due to three protocol-level gaps:
1. **Fragmented lifecycle and context management:** Neither protocol standardizes primitives for maintaining consistent, versioned execution context.
2. **Lack of self-evolution:** Prompts and resources are treated as externally maintained assets rather than components refined from execution feedback under traceable versioning.
3. **Environments are not first-class:** They are delegated to application-specific runtimes rather than managed components with explicit boundaries.

To address these, the authors propose the **TEA protocol**, treating environments, agents, and tools as explicitly managed components. Based on TEA, they develop **AGENTORCHESTRA**, a hierarchical multi-agent framework that uses a central planner to decompose objectives and delegate sub-tasks to specialized agents with localized tool ownership.

---

## 2. Related Work
- **Tool and Agent Protocols:** MCP unifies tool integration; A2A enables agent-to-agent messaging. TEA extends these by integrating tools, environments, and agents into a unified context-aware framework with lifecycle management.
- **General-Purpose Agents:** Frameworks like MetaGPT, OpenHands, and smolagents advance unified perception and tool-augmented action, but often lack unified protocols for cross-layer resource management.

## 3. The TEA Protocol
The TEA Protocol is designed around coroutine-based asynchronous execution and comprises three primary layers:

### 3.1 Basic Managers
Six specialized managers provide foundational services:
1. **Model Manager:** Abstracts heterogeneous LLM backends.
2. **Prompt Manager:** Handles prompt lifecycle and versioning.
3. **Memory Manager:** Coordinates persistence via session-based concurrency control.
4. **Dynamic Manager:** Enables runtime code execution and serialization.
5. **Version Manager:** Maintains evolution histories for all components.
6. **Tracer:** Records comprehensive execution trajectories for audit, debugging, and dataset synthesis.

### 3.2 Core Protocols
Each protocol is implemented via a context manager (for lifecycle engineering) and a server (for standardized orchestration):
- **Tool Context Protocol (TCP):** Extends MCP with integrated context engineering, lifecycle management, versioning, and semantic retrieval.
- **Environment Context Protocol (ECP):** Formalizes computational environments as first-class components with distinct observation and action spaces.
- **Agent Context Protocol (ACP):** Establishes a unified framework for the registration, representation, and orchestration of autonomous agents.

### 3.3 Protocol Transformations
Six fundamental categories enable dynamic role reconfiguration:
- **A2T (Agent-to-Tool):** Encapsulates an agent’s capabilities into a standardized tool interface.
- **T2A (Tool-to-Agent):** Treats tools as operational actuators for an agent’s goals.
- **E2T (Environment-to-Tool):** Converts environment actions into standardized tool interfaces.
- **T2E (Tool-to-Environment):** Elevates a collection of tools into an environment abstraction.
- **A2E (Agent-to-Environment):** Encapsulates an agent as an interactive environment for other agents.
- **E2A (Environment-to-Agent):** Embeds reasoning into an environment’s dynamics, transforming it into an autonomous agent.

### 3.4 Self-Evolution Module
Enables agents to continuously improve by optimizing evolvable components (prompts, code, solutions) during task execution using **TextGrad** (gradient-based refinement) and **Self-reflection**. Optimized components are registered as new versions.

## 4. AgentOrchestra
A concrete instantiation of the TEA Protocol, featuring a hierarchical multi-agent architecture.

### 4.1 Agent Design Principles
Agents operate in a continuous perception–interpretation–action cycle, interacting with six core components: Agent (ACP), Environment (ECP), Model, Memory, Observation, and Action (TCP).

### 4.2 Planning Agent
The central orchestrator. It interprets user goals, decomposes them into sub-tasks, dispatches them to specialized sub-agents/tools, and tracks global progress with automatic replanning under environment shifts or failures.

### 4.3 Specialized Sub-Agents
1. **Deep Researcher Agent:** Multi-round research workflows with parallel breadth-first searches across multiple engines.
2. **Browser Use Agent:** Automated, fine-grained web interaction (DOM-level and pixel-level operations).
3. **Deep Analyzer Agent:** Multi-step reasoning on heterogeneous multimodal data (text, PDFs, images, audio, video, zip).
4. **Tool Generator Agent:** Automated creation, retrieval, and systematic reuse of TCP-compliant tools.
5. **Reporter Agent:** Aggregates evidence and composes structured markdown with automatically deduplicated references.

## 5. Empirical Studies
Evaluated on four benchmarks: GAIA, HLE, AIME, and GPQA-Diamond.

### 5.1 Performance across Benchmarks
- **GAIA:** AGENTORCHESTRA Evolved achieves **89.04%** on the Test set and **93.33%** on the Validation set (State-of-the-Art), showing strong scaling on harder partitions (Level 2: 85.53%, Level 3: 81.63%).
- **HLE:** Achieves **59.6**, improving over Vanilla by 7.97% and outperforming strong baselines like GPT-5.5 Pro (57.2) and Kimi K2.6 Thinking (54.0).
- **GPQA & AIME:** Self-evolution consistently improves performance across all five tested model backbones, with the largest gains on lower- and medium-reasoning models (e.g., gpt-4.1 improved by 71.38% on AIME24).

### 5.2 Ablation Studies
- **Sub-agent effectiveness:** Adding Deep Researcher and Browser Use Agent significantly boosts early information acquisition. Deep Analyzer improves hard multimodal cases. Tool Generator provides the largest late-stage gain (average score from 79.07 to 89.04).
- **Efficiency:** Simple tasks take ~30s / 5k tokens; medium tasks ~3min / 25k tokens; complex multimodal tasks ~10min / 100k tokens.
- **Self-evolution & Tool evolution:** The Tool Generator autonomously generated over 50 specialized tools during evaluation, achieving a 30% reuse rate.

---

## 6. Conclusion & 7. Limitations
**Conclusion:** TEA Protocol and AGENTORCHESTRA demonstrate that explicit protocol design, hierarchical orchestration, and self-evolution lead to robust and adaptive multi-agent systems.

**Limitations:**
1. **System Complexity:** Steeper learning curve for developers (mitigated by providing templates and tutorials).
2. **Communication Overhead:** Formal protocols may introduce marginal latency (future work: optimize serialization and asynchronous execution).
3. **Dependence on Underlying Models:** Cannot fully compensate for foundation model hallucinations.
4. **Potential Risks:** Misuse for malicious automation and privacy/security risks when accessing local environments (requires sandboxing and human-in-the-loop verification).
